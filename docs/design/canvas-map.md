# Canvas → app map

How the six design-canvas boards map onto the app as it stands on `main` (after the Phase 2 cut).
Read this before planning or building any screen. Nothing here is built yet.

- Canvas: https://claude.ai/artifact/DEsTmRtTRB5vP2G5ugddyE · snapshot in `docs/design/canvas/` (refreshed 2026-11-11, 33 boards)
- The canvas wins over spec prose. Where the canvas is silent, the item is listed under **Not drawn** and needs an owner decision; it is not to be invented.
- "Exists" means the code is on `main` today. "New" means nothing exists.

| `read` — **Reading list** | `/reading` | New | New page |
| `wifi` | `/wifi` | Exists | Restyled; same behaviour |

| Admin hub / Overview | `/admin` | Exists as one page with four tabs (Today, Approvals, People, Publish) | Rebuilt: hub on phone, dashboard on desktop |
| Admin · Today | `/admin/today` | Part of the `today` tab | Phone-only page; on desktop its content is the Overview |
| Admin · Office days / People & office days | `/admin/people` | Part of the `people` tab (`access-list`, `leave-overview`) | New page |
| Admin · Speak up inbox | `/admin/speak-up` | `grievance-list` inside `/admin` | Own page |
| Admin · Snack shelf | `/admin/snacks` | Removed in the cut (`/admin/pantry` redirects to `/`) | New page |
| Admin · Wi-Fi reports | `/admin/wifi` | Section inside `/admin` | Own page |
| Sign-in | `/sign-in` | Exists | Restyled; no board |

Route groups stay as they are: `app/(member)/` guarded by `requireUser`, `app/(admin)/` by `requireAdmin`, and `proxy.ts` sends signed-out visitors to `/sign-in`. New admin pages go under `app/(admin)/admin/…` so the existing guard covers them without new code.

Link builders in `lib/journey.ts` (`boardHref`, `eventHref`, `attendanceHref`) are what notifications and push payloads use. They change in one place when the routes move; old URLs get redirects, same as the cut did.

## 7. Decisions and what is still not drawn

| Question | Decision |
|---|---|
| Bell | Opens a separate Notifications page on every size. Never the Feed, never a popover |
| Client data layer | TanStack Query for server data. No Zustand unless a real cross-screen client state appears |
| Who creates polls and kudos | Anyone. "New post" has four kinds: Quote, Feedback, Kudos, Poll |
| Digital ID card | Dropped |
| Check-out and location | No check-out; location verification stays (drawn in `D-CheckIn-Location`) |
| Old pings in the database | Kept for now; no purge |
| Laptop and tablet inner pages, admin sub-pages | Drawn on the canvas first (done 2026-11-11), then built |
| Settings vs Account | One page |

Still not drawn:

1. **Phone prototype catch-up.** "New post" still offers only Quote and Feedback. (The bell was fixed on 2026-11-11: it opens the Notifications screen.)
2. **Admin in-place actions on the Feed**: announcement composer, event editor, "remove post".
4. **Admin on the phone**: People, Speak up inbox and Wi-Fi reports. **Admin on a tablet**: nothing drawn.
5. **Sign-in, Help, error and empty states** (other than the empty Feed).
7. **Agreed features with no board:** weekly mood check-in, "who's out", water log, break reminder, team hydration goal, Friday recap.
