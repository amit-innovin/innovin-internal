# Feed, Material 3 (Stage 3): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `/feed` as the catch-up Feed from the prototype, with seen tracking, a "Still open" list, a four-kind composer, and important announcements that people acknowledge once.

**Architecture:**
- **Pure rules** live in a new `lib/feed-rules.ts`: new posts, open items, poll hiding and the "your posts" lines.
- **`feedFor`** in `lib/feed.ts` applies those rules for the viewer.
- **Store additions:** a per-person `feedSeenAt` watermark, plus fields and acknowledgements on announcements.
- **UI:** the page is `components/feed/*`. The important-announcement sheet and the Feed badge sit in the M3 shell.

**Tech Stack:** Next.js 16.4.6, React 19, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-m3-feed-design.md`. The prototype is `docs/design/m3/Prototype.dc.html` (the Feed tab, the `imp` sheet and the `np` composer) plus `DesktopPrototype.dc.html`.

## Review Focus

1. **A post created while you're mid-stack.** The watermark only moves forward to the time of a card you saw, so the new post is still new on your next visit. Test in Task 2 (`newPostIds`, with a post newer than the watermark and older than "now").
2. **Poll results before voting.** The server must not send percentages or vote counts for an open poll you haven't voted in, including in the JSON. Test in Task 3 (API): the response has `pct` and `votes` set to null before voting and numbers after.
3. **Important announcement acknowledged on one device.** The sheet must not reappear on another device or after a reload. Test in Task 6 (e2e): acknowledge, reload, and expect no dialog.
4. **A member calling `POST /api/events`.** This must be refused, 401 or 403. Test in Task 3.
5. **Swiping on a card's own buttons.** Tapping "I'm in" or a poll option must not advance the stack. Test in Task 5 (e2e): tap "I'm in" on the event card, and the counter is unchanged.

### Task 1: Store (seen watermark, announcement fields, acknowledgements)

**Files:** `lib/types.ts`, `lib/jsonstore.ts`, `lib/pgstore.ts`, `tests/store/contract.ts`

**Interfaces (produces):**

- `countAnnouncementAcks(ids: string[]): Promise<Record<string, number>>`.

  - `ALTER TABLE announcements ADD COLUMN IF NOT EXISTS important boolean NOT NULL DEFAULT false`, plus `author_name text` and `pinned_until text`;
  - `announcement_acks(announcement_id text, email text, at timestamptz, PRIMARY KEY(announcement_id,email))`.

### Task 2: Pure feed rules

**Files:** Create `lib/feed-rules.ts` and `tests/unit/feed-rules.test.ts`.

**Interfaces (produces):**
- `defaultSeenAt(today: string): string`. This is `${addDays(today,-1)}T00:00:00+05:30` as an ISO string.
- `newPostIds(posts: { id: string; at: string; type: string; important?: boolean }[], seenAt: string, now: number): string[]`:
  - It keeps posts with `at > seenAt` and `at` no older than 7 days.
  - It drops important announcements.
  - It returns them oldest first.
- `openItems(posts: FeedPost[], now: number): string[]`. It returns event ids not yet answered (`!mine`, not cancelled, and `startsAt > now`) and poll ids where nothing is `mine` and the poll isn't `closed`.
- `hideUnvoted(poll)`. When nothing is `mine` and the poll isn't closed, it returns the options with `votes: null, pct: null` and `total: null`.
- `myPostLine(post): string | null`. It gives "You gave kudos to {toName}", "Your poll: {question}", "You shared a quote" or "You shared feedback".

- [ ] **Step 1:** Write the tests below, then run `npx vitest run tests/unit/feed-rules.test.ts`. Expected: FAIL.
  - Review Focus 1: a post at T+1 stays new when the watermark is T.
  - A post older than 7 days is not new.
  - Important announcements are excluded.
  - The order is oldest first.
  - `openItems`, for answered and unanswered events and polls, and for closed polls.
  - `hideUnvoted`, before and after a vote.
  - Every `myPostLine` string.
- [ ] **Step 2:** Implement, then run the same command. Expected: PASS.
- [ ] **Step 3:** Commit `feat(feed): catch-up rules`.

### Task 3: Feed data and routes

**Files:**
- Modify `lib/feed.ts`, `lib/notices.ts` (a `mine` flag computed on the server), `app/api/feed/route.ts`, `app/api/events/route.ts` (JSON POST becomes admin-only) and `app/api/announcements/route.ts` (accepts `important`, `pinnedUntil` and the author name; the admin GET adds `seen` counts).
- Create `app/api/feed/seen/route.ts`, `app/api/announcements/important/route.ts` and `app/api/announcements/ack/route.ts`.
- Test: `e2e/api.spec.ts`.

**Interfaces (produces):**
- `FeedPost`:
  - every variant gains `mine?: boolean` (the viewer wrote it);
  - announcements gain `important`, `authorName` and `pinnedUntil`;
  - the poll's `options[].votes`, `options[].pct` and `total` become `number | null`.
- `Feed` gains `seenAt: string`, `newIds: string[]` and `open: string[]`.
- Posts stay newest first for "Earlier". Important announcements that the viewer has acknowledged and that are still pinned are flagged with `acked: true`.
- `POST /api/feed/seen { at }` → 200 `{ seenAt }`. An `at` in the future is clamped to now. A bad body gets 400.
- `GET /api/announcements/important` → `{ announcement: { id, title, body, authorName } | null }`. It returns the oldest important announcement that is not acknowledged and has `pinnedUntil >= today`.
- `POST /api/announcements/ack { id }` → 200; an unknown id gets 404.

- [ ] **Step 1:** Add the API tests, then build and run `npx playwright test api.spec --project=api --no-deps`. Expected: the new tests FAIL.
  - Seen moves forward and never back.
  - Poll `pct`/`votes` are null before voting and numbers after (Review Focus 2).
  - A member's JSON `POST /api/events` gets 401 (Review Focus 4). Update the existing tests that create events as a member so they use the admin context instead.
  - Important flow: an admin posts with `important: true` and `pinnedUntil` today+3. A member's GET returns it; after acking, the GET returns null; the admin's GET of announcements shows `seen: 1`.
- [ ] **Step 2:** Implement, then run `npm run build` and the same command. Expected: PASS. Also run `npx vitest run` and `npx tsc --noEmit`.
- [ ] **Step 3:** Commit `feat(feed): catch-up data, seen and important-announcement routes`.

**Interfaces (consumes):** Task 4 hooks, `PageHero` (`page="feed"`), `Sheet`, `Button`, `Card`, `StatusChip` and `Avatar`.

**Behaviour:**
- **Stack, phones (<1100px):**
  - It shows the posts in `newIds`, with the counter `"{i} / {N}"` and Back/Next buttons.
  - Pointer swipe: a 110px threshold, ignored when the pointer starts on a button, link or input.
  - Showing a card calls `useMarkFeedSeen` with that card's `at`, but only when it's greater than `seenAt`.
- **Desktop (≥1100px):** "NEW SINCE YESTERDAY · N", then the cards, then the caught-up separator.
- **Card actions:**
  - Kudos and quote use "Appreciate" ↔ "Appreciated", which is the 👍 reaction.
  - Birthday cards come from `celebrations`, use Lappy, and have "Send a wish", which opens the composer as Kudos with the To set.
- **Composer:**
  - Poll sends `closesOn: addDays(today, 3)` and exactly two options.
  - Quote and feedback send `color: "purple", anonymous: false`.
  - The "To" picker is alphabetical with a search box.
- **Retired URLs:** `?filter=` is ignored. `/events` and `/board` keep redirecting to `/feed`, as now.
