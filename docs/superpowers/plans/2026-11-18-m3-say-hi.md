# Say hi (Stage 7): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opt-in waves and invites between people in the office, as drawn.

**Spec:** `docs/superpowers/specs/2026-11-18-m3-say-hi-design.md`.

**Global Constraints:** Same as the earlier stages. Store changes must also pass the Postgres contract tests.

## Review Focus

1. **A fourth send in a day:** returns 409.
2. **Sending to someone opted out or not in the office:** returns 403.
3. **Replies:** only the recipient can answer, only once, and only to an invite (not a wave).
4. **Opt-out:** someone who turns Say hi off disappears from others' Wave options at once, and gets nothing new.
5. **Push content:** pushes carry no names or message text.

Tests: Task 1 (contract), Task 2 (API), Task 3 (e2e).

### Task 1: Store

`sayHi` and `setSayHi`, plus the `hi_messages` methods. Write the contract tests first (RED), then implement both stores. Check against JSON and Postgres, then commit.

### Task 2: Routes and data

- `/api/hi`, `/api/hi/reply` and `/api/hi/setting`.
- `daysView` returns the people in office with their Say hi flag, plus `me.sayHi` and `sent`.
- Notifications get the hi items, including replies to the sender.
- Write the API tests for Review Focus 1–5. RED on the old build, then GREEN. Commit.

### Task 3: Screens

- Home: Wave buttons, the sheet, and the off line.
- Account: the Say hi switch in Notification settings.
- Notifications: invite items with I'm in / Not today.
- Write the e2e tests: opt in for both people, check in, wave, recipient sees it; invite chai now, recipient taps I'm in, sender sees the reply; the off line shows Turn on.
- RED, then GREEN. Commit.

### Task 4: Gates and review

Run tsc, vitest (JSON and Postgres) and the full suite. Then a fresh review and one fix pass.
