# Tea & snacks, Material 3 (Stage 4): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `/snacks` from the prototype with these features:
- two tea rounds a day, each with its own answer;
- one anonymous snack pick per person per day;
- cut-offs enforced by the server;
- an office check-in gate;
- admin-set times.

**Architecture:**
- **Pure rules** live in `lib/snacks-rules.ts`: the current round, whether picking is open, and the counts.
- **Store additions:** `snack_picks`, round and answer columns on `tea_rounds`, and a `settings` key/value table.
- **Routes:** `/api/tea` and `/api/snacks` are extended, and `/api/admin/snack-times` is new.
- **UI:** components go under `components/snacks/`. Home's tea row reads the same tea data.

**Tech Stack:** Next.js 16.4.6, React 19, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-18-m3-snacks-design.md`. The prototype is the Snacks tab of `docs/design/m3/Prototype.dc.html` (demo props `teaTime` and `snackState`), plus `DesktopPrototype.dc.html` and `M3AdminSnacks.dc.html`.

## Global Constraints

The Feed plan's global constraints all apply:
- branch, git identity and commit trailer;
- the four-file store rule;
- no new dependencies;
- hooks live in `lib/queries.ts`;
- `m3 m3-page`;
- the gates and the build-before-Playwright rule.

Additionally:
- **Times are IST.** Defaults are `amAt 11:00`, `amClose 10:45`, `pmAt 16:00`, `pmClose 15:30` and `orderAt 12:00`.
- **Gate:** tea and pick writes need an office check-in today. Otherwise the server answers 403 `{code:"not-in-office"}`.
- **Anonymity:** snack pick voter refs and suggestion voters never leave the server, not even for admins. Tea names go only to admins.

## Review Focus

1. **Answering tea at 10:46.** Refused with 409 `closed`, and the card shows the closed state, not an error toast. Test in Task 2 (rules) and Task 3 (API, by setting `amClose` to a time already past).
2. **Switching your snack pick.** Exactly one pick per person per day. Counts move from the old item to the new one. Test in Task 1 (contract) and Task 3 (API).
3. **Old tea rows.** Rows from before this change still count as the afternoon round, as "yes". Test in Task 1 (contract: a row written without round or going reads as round `pm`, going true).
4. **A remote person.** Writes are refused on the server even if the request skips the UI. Test in Task 3.
5. **An admin's times are invalid** (a cut-off at or after its round). Rejected with 400, and the old times stay. Test in Task 3.

### Task 1: Store

**Files:** `lib/types.ts`, `lib/jsonstore.ts`, `lib/pgstore.ts`, `tests/store/contract.ts`

**Produces:**
- `type TeaAnswer = { date: string; round: "am" | "pm"; email: string; going: boolean }`.
  - `setTeaAnswer(date, round, email, going: boolean | null)`. `null` removes the answer.
  - `listTeaAnswers(date): Promise<TeaAnswer[]>`.
  - The old `setTea` and `listTea` stay as thin wrappers over round `pm`, for older callers such as the admin overview.
  - pg changes: `ALTER TABLE tea_rounds ADD COLUMN IF NOT EXISTS round text NOT NULL DEFAULT 'pm'` and `ADD COLUMN IF NOT EXISTS going boolean NOT NULL DEFAULT true`. The primary key moves to `(date, round, email)` through a guarded migration.

### Task 2: Pure rules

**Files:** create `lib/snacks-rules.ts` and `tests/unit/snacks-rules.test.ts`.

**Produces:**
- `type SnackTimes = { amAt: string; amClose: string; pmAt: string; pmClose: string; orderAt: string }` and `DEFAULT_SNACK_TIMES`.
- `validTimes(t): boolean`. True when every value is `HH:MM` and each round's close is before its round.
- `istClock(now: Date): string`. Returns "HH:MM" in IST.
- `currentRound(now, t): { id: "am" | "pm"; at: string; closesAt: string; open: boolean; next: "pm" | null } | null`. It returns the morning round until 11:00, then the afternoon round until 4 PM, then `null` (there's no more tea today). `open` means `clock < closesAt`.
- `pickOpen(now, t, orderedToday: boolean): boolean`.
- `pickCounts(picks, itemIds): Record<string, number>`.

Steps:
- [ ] Write the tests:
  - 10:44 is open, morning; 10:46 is closed, morning, with `next` "pm"; 11:30 is open, afternoon; 15:31 is closed, afternoon; 16:30 is `null`.
  - `validTimes` rejects 11:00/11:00 and "9am".
  - `pickOpen` is false at 12:00 and false when the day is already ordered.

  Run them. Expected: FAIL.
- [ ] Implement, then run them again. Expected: PASS. Then commit.

### Task 3: Routes

**Files:**
- Modify `app/api/tea/route.ts` and `app/api/snacks/route.ts`.
- Create `app/api/admin/snack-times/route.ts`.
- Test: `e2e/api.spec.ts`.

**Behaviour:**
- **Times:** routes read them with `getSetting("snackTea") ?? DEFAULT_SNACK_TIMES`.
- **Office check:** "In the office" means today's attendance `dayMode` is `"office"`.
- **Tea responses:**
  - GET → `{ round, mine, next }`.
  - Admins also get `counts: { am, pm }` and `names: { am: string[], pm: string[] }`, with first names only.
- **Tea answers:**
  - POST `{ round, going }`.
  - A round other than the current one → 409 `wrong-round`.
  - A closed round → 409 `closed`.
  - Not in the office → 403 `not-in-office`.
- **Snacks:**
  - GET adds `today: { open, orderAt, ordered, picks, mine }`. "Ordered" means an admin marked an item ordered today.
  - PATCH `{ id, action: "pick" }` requires an office check-in, `pickOpen`, and an item on the shelf.
  - PATCH `{ id, action: "unpick" }` removes your pick.
- **`/api/admin/snack-times`:**
  - Admin only.
  - PATCH accepts `{ amAt, amClose, pmAt, pmClose, orderAt }` and returns 400 unless `validTimes`.

Steps:
- [ ] Write the API tests, covering Review Focus 1, 2, 4 and 5.
  - Set the times through the admin route so the current round is closed (for example `amClose` and `pmClose` "00:01"), then restore the defaults in a `finally`.
  - Build and run. Expected: FAIL.
- [ ] Implement, then build and run again. Expected: PASS. Then commit.
